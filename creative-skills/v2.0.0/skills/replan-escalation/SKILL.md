# 重规划与升级处理

## 用途

当局部修复解决不了问题（修复次数用完、问题出在规划本身、篇幅在当前规划下无法达标、主线偏离），回到规划层重新安排，而不是继续在正文上打补丁。

## 何时使用 / 不适用

- **使用：** 局部修复用完次数仍未通过时；审核判定是结构性问题时；章节规划无法在篇幅区间内承载时。
- **不适用：** 可以局部修复的问题（由局部修复负责）。

## 方法

1. **【补写】先诊断失败原因。** 常见原因：
   - 规划太薄：场景和节拍不足以撑起篇幅；
   - 规划太满：内容超出篇幅，只能被压成概述；
   - 目标重复：本章目标与之前的章节重复，没有新东西可写；
   - 与已有事实冲突：规划要求的情节和已提交的正文或设定矛盾；
   - 主线偏离：本章或本段离开了主线。
2. **按原因选择处理方式**（来源：修改润色，情节修改；长篇架构，中期卡文的解决）：
   - 太薄：增加场景或节拍（新的受挫、发现、选择），或与下一章合并；
   - 太满：拆成两章，或把次要内容移到后文；
   - 目标重复：换一个能带来新推进的目标；
   - 事实冲突：改规划，使其服从已提交的事实；
   - 主线偏离：砍掉无关支线，把本章重新连回主线。
3. **主线不变，细节可调。** 重新规划只调整本章或本段的具体安排，不改核心冲突和结局方向。（来源：大纲方法，调整原则）
4. **评估连锁影响。** 列出受影响的后续章节、伏笔、人物弧节点，一并更新。（来源：大纲方法，调整方法）
5. **【补写】重新生成，不沿用失败稿。** 规划改动后，正文按新规划重新生成，不在失败的旧稿上修补。
6. **【补写】需要人决定时上报。** 涉及核心冲突、结局方向、主要人物命运的改动，或自动处理仍失败时，停止并把诊断和可选方案交给用户决定。

## 失败写法与改法

| 失败写法 | 改法 |
|---|---|
| 修复了五次篇幅仍不足，继续第六次 | 回到规划，诊断是否太薄 |
| 为了让本章通过，改掉了已提交章节的事实 | 改规划，服从已提交的事实 |
| 重新规划时顺手改了结局 | 只调整本章或本段，重大改动上报用户 |
| 规划改了，但正文沿用旧稿补丁 | 按新规划重新生成 |

## 示例（自写）

```
情况：第 2 章两次重写后仍只有约 1500 字（区间 2000–3000）
诊断：规划太薄——只有 1 个场景、3 个节拍；且目标"决定调查"与第 1 章结尾重复
处理：
  1. 换目标："查明委托人的记忆为何每天被二次覆盖"（新推进）
  2. 增加场景：档案查询受阻（3 节拍）、深夜回访（3 节拍），共 3 个场景 8 个节拍
  3. 连锁影响：原第 3 章的"发现覆盖"前移到本章，第 3 章目标改为"追查覆盖者"
  4. 按新规划重新生成正文，不沿用 1500 字旧稿
上报：无（未涉及核心冲突和结局）
```

## 注入要点·修复

> 局部修复失败或判定为结构问题时注入，不超过 600 字。

先诊断失败原因：规划太薄、规划太满、目标重复、与已有事实冲突，还是主线偏离。太薄就增加真正的场景和节拍，或与下一章合并；太满就拆章或后移；目标重复就换成有新推进的目标；事实冲突就改规划服从已提交的事实；偏离就砍掉支线连回主线。只调整本章或本段，核心冲突和结局方向不变。列出受影响的后续章节、伏笔、弧线节点。按新规划重新生成正文，不沿用失败稿。涉及核心冲突、结局或主要人物命运时，上报用户决定。
