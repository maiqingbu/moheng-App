# 配角群像设计：反模式

## AP-S01 问题3:次要视角喧宾夺主
- 类型：`source`
- 来源：`WWC-06-016`
- 识别信号：表现: 本来主角是A结果写着写着B角色的视角内容更多更精彩A反而像配角 解决方法: 1. 统计视角比例 主角视角:60-70% 其他重要角色:20-30% 次要角色:5-10%2. 主线永远跟随主角 其他视角是辅助线3. 如果B更精彩 考虑是不是选错主角了?

## AP-S02 问题2:视角切换过频
- 类型：`source`
- 来源：`WWC-06-015`
- 识别信号：表现: 几乎每段都换一个视角读者眼花缭乱无法投入任何一个角色 解决方法: 原则:一个完整场景用一个主视角如果确实需要切换:- 用明确的分隔- 每个视角至少维持一个场景- 不要每段都换

## AP-S03 误区2:视角就是"看到"
- 类型：`source`
- 来源：`WWC-06-031`
- 识别信号：错误认知: 视角只是描写角色看到了什么 正确理解: 视角包括:- 看到的(视觉)- 听到的(听觉)- 想到的(心理)- 感受到的(情感)- 认知的(世界观)同样一件事不同角色的理解和感受完全不同

## Project policy guardrails
- 不得一次性制造全书角色百科
- 只设计当前阶段必要角色
- 每个关键配角必须有独立欲望而非只服务主角
- 任何 HARD/Canon/Knowledge 冲突优先于文学质量建议。
- 不得读取未来不该暴露给当前 POV/Renderer 的信息。
- 不得把 Skill 自身知识当成项目事实。
- 不得读取或泄露当前 POV/Renderer 不可见的未来信息。
- 不得以文学质量评分覆盖 HARD 失败。
