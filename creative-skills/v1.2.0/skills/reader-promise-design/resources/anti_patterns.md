# 读者承诺与期待设计：反模式

## AP-S01 问题四：缺少爽点
- 类型：`source`
- 来源：`WWC-11-028`
- 识别信号：表现： 前三章没有爽感 只有铺垫没有高潮 读者提不起兴趣 解决方法： 第一章必有小爽点 第三章要有打脸/装逼 不要过度压抑 给读者期待

## Project policy guardrails
- Reader Promise 不是 Canon
- 不得强制每章 cliffhanger
- 输出必须可被后续 ReaderDesire evaluator 使用
- 任何 HARD/Canon/Knowledge 冲突优先于文学质量建议。
- 不得读取未来不该暴露给当前 POV/Renderer 的信息。
- 不得把 Skill 自身知识当成项目事实。
- 不得读取或泄露当前 POV/Renderer 不可见的未来信息。
- 不得以文学质量评分覆盖 HARD 失败。
