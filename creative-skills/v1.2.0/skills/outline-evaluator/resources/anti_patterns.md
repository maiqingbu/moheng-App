# 总纲/卷纲结构评估：反模式

## AP-S01 问题4：线索断了
- 类型：`source`
- 来源：`WWC-05-019`
- 识别信号：表现： 某条线推了一半不推了 读者一直等后续 作者自己忘了 预防： 建立线索管理表 定期检查 该收束时收束 不要虎头蛇尾

## AP-S02 问题1：写到中期卡文
- 类型：`source`
- 来源：`WWC-18-014`
- 识别信号：原因： 前期埋的坑太多 没有整体规划 主线不清晰 失去方向感 解决： 重新梳理主线 列出所有伏笔 制定下一阶段大纲 砍掉不必要的支线

## AP-S03 问题2:越写越偏离大纲
- 类型：`source`
- 来源：`WWC-19-021`
- 识别信号：是否要遵守大纲? 看情况:偏离后更好:说明你写作中有新灵感可以调整大纲跟上偏离后更差:赶紧拉回来按大纲走原则:大纲是指引不是枷锁可以调整但主线不能丢

## AP-S04 问题1：线索太多理不清
- 类型：`source`
- 来源：`WWC-05-016`
- 识别信号：原因： 一开始就开太多线 没有规划就随意加线 忘记收束某些线 解决： 列出所有线索清单 标注主次和状态 砍掉不必要的线 合并相似的线 预防： 开线要慎重 每条线都要有意义 定期梳理线索

## AP-S05 问题2：切换太频繁
- 类型：`source`
- 来源：`WWC-05-017`
- 识别信号：表现： 每章都换视角 每千字就切线 读者跟不上 解决： 减少切换频率 单一视角至少持续3-5章 切换要有明确标识 建议： 新手：每10章切换一次 熟手：每5章切换一次 高手：根据剧情需要灵活切换

## Project policy guardrails
- 不得用“宏大/精彩”空泛评分
- 必须指出具体结构风险
- 与开篇 Canon 冲突直接 HARD flag
- 任何 HARD/Canon/Knowledge 冲突优先于文学质量建议。
- 不得读取未来不该暴露给当前 POV/Renderer 的信息。
- 不得把 Skill 自身知识当成项目事实。
- 不得读取或泄露当前 POV/Renderer 不可见的未来信息。
- 不得以文学质量评分覆盖 HARD 失败。
