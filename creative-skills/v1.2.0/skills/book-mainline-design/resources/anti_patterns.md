# 全书主线设计：反模式

## AP-S01 错误1:冲突单一
- 类型：`source`
- 来源：`WWC-03-032`
- 识别信号：表现: 从头到尾只有一个冲突主角vs反派没有其他太单调! 解决: 多条冲突线:主线冲突+支线冲突外部冲突+内部冲突人与人+人与环境

## AP-S02 错误4:为冲突而冲突
- 类型：`source`
- 来源：`WWC-03-035`
- 识别信号：表现: 强行制造冲突角色行为不合理只为了有冲突很假! 解决: 冲突要自然产生:- 利益冲突- 理念不合- 误会- 阵营对立符合逻辑!

## AP-S03 问题3：主线失焦
- 类型：`source`
- 来源：`WWC-18-016`
- 识别信号：原因： 支线太多喧宾夺主 忘记初心 跟风写热门元素 东一榔头西一棒子 解决： 回归主线 砍掉无关支线 聚焦核心冲突 不要什么都写

## AP-S04 错误3:冲突解决太容易
- 类型：`source`
- 来源：`WWC-03-034`
- 识别信号：表现: 看起来很严重的危机一章就解决了轻轻松松没有压迫感! 解决: 重要冲突要有过程:- 多次交锋- 策略调整- 实力提升- 最终解决不要太轻易解决!

## Project policy guardrails
- 只到阶段/卷意图粒度
- 不得预生成逐章事件清单
- 每阶段必须有状态变化而非换地图
- 任何 HARD/Canon/Knowledge 冲突优先于文学质量建议。
- 不得读取未来不该暴露给当前 POV/Renderer 的信息。
- 不得把 Skill 自身知识当成项目事实。
- 不得读取或泄露当前 POV/Renderer 不可见的未来信息。
- 不得以文学质量评分覆盖 HARD 失败。
