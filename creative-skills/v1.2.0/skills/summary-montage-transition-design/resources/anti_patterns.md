# 概述/蒙太奇/过渡设计：反模式

## AP-S01 错误2:转换混乱
- 类型：`source`
- 来源：`WWC-04-019`
- 识别信号：表现: 多个场景交叉没有明确标识读者分不清现在在哪 解决: 1. 明确标识 用分隔符/标题/标识词2. 每个场景有明显特征 让读者能区分3. 不要切换太频繁 一个场景说完整

## AP-S02 错误3:无意义转换
- 类型：`source`
- 来源：`WWC-04-020`
- 识别信号：表现: 转到某个场景写了一点无关紧要的内容又转回来读者:这段有什么用? 解决: 转换要有目的:- 推动剧情- 增加信息- 制造悬念- 展现对比无意义的转换=浪费篇幅删掉!

## AP-S03 错误4:转换失衡
- 类型：`source`
- 来源：`WWC-04-021`
- 识别信号：表现: 主角场景简略配角场景冗长主次颠倒! 解决: 场景篇幅分配:主角场景:60-70%重要配角:20-30%次要角色:5-10%把握主次

## Project policy guardrails
- SUMMARY/MONTAGE 不因缺少强 sceneTurn 被 HARD BLOCK
- 不得把关键选择压缩掉
- 任何 HARD/Canon/Knowledge 冲突优先于文学质量建议。
- 不得读取未来不该暴露给当前 POV/Renderer 的信息。
- 不得把 Skill 自身知识当成项目事实。
- 不得读取或泄露当前 POV/Renderer 不可见的未来信息。
- 不得以文学质量评分覆盖 HARD 失败。
