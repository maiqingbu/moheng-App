# Arc 局部阶段设计：反模式

## AP-S01 错误2:冲突不升级
- 类型：`source`
- 来源：`WWC-03-033`
- 识别信号：表现: 开局打小怪中间打小怪后期还是打小怪没有进步感! 解决: 敌人要越来越强格局要越来越大困难要越来越大

## AP-S02 错误1:冲突单一
- 类型：`source`
- 来源：`WWC-03-032`
- 识别信号：表现: 从头到尾只有一个冲突主角vs反派没有其他太单调! 解决: 多条冲突线:主线冲突+支线冲突外部冲突+内部冲突人与人+人与环境

## AP-S03 错误4:为冲突而冲突
- 类型：`source`
- 来源：`WWC-03-035`
- 识别信号：表现: 强行制造冲突角色行为不合理只为了有冲突很假! 解决: 冲突要自然产生:- 利益冲突- 理念不合- 误会- 阵营对立符合逻辑!

## AP-S04 问题4：节奏失控
- 类型：`source`
- 来源：`WWC-18-017`
- 识别信号：原因： 一直高潮读者疲劳 一直平淡读者流失 没有张弛 缺乏变化 解决： 制定节奏曲线图 有意识调控快慢 高潮后必有过渡 保持节奏变化

## Project policy guardrails
- 不得成为第二套卷纲
- 只保留事件/状态级设计，不写逐句剧情
- 任何 HARD/Canon/Knowledge 冲突优先于文学质量建议。
- 不得读取未来不该暴露给当前 POV/Renderer 的信息。
- 不得把 Skill 自身知识当成项目事实。
- 不得读取或泄露当前 POV/Renderer 不可见的未来信息。
- 不得以文学质量评分覆盖 HARD 失败。
