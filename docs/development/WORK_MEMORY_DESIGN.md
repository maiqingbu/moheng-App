# WM-1 作品长期记忆设计（负责人 2026-11-01 已确认方向）

负责人 2026-11-01：每一部新建作品要有独立的长期记忆。作品目标约 2000 万字（几千章），记忆库会很复杂，需要先研究清楚再实现。素材：负责人提供的视频《面试官问：你的 Agent 怎么记住三年前说过的话？》（约 3 分 22 秒）。

---

## 1. 视频要点

| # | 要点 | 原话大意 |
|---|---|---|
| 1 | 基础做法 | 把对话里的关键信息抽出来，向量化后存进向量库；下次用当前问题检索，把召回的记忆拼进上下文。 |
| 2 | 只靠向量不行 | “这个饼干能不能吃”和“我对花生过敏”语义不接近，纯相似度召不回。要改成**混合检索**：存储时把**时间、实体、类型**写成结构字段；检索时先按结构条件（用户、记忆类型）把范围框住，再在剩下的里面按相似度排序。 |
| 3 | 时间的两种用法 | 一是**过滤**（某个时间之后说过的话）；二是**加权**（同样相关，近的权重高）。但**时间权重按记忆类型给**：过敏这种事实三年前和三天前一样有效，不是一刀切。 |
| 4 | 更新不删除 | 同一属性有新值（Python → Go）时两条都保留，带时间戳，标成同一属性的不同版本。检索取最新那条当当前事实，历史可追溯。删除会让“为什么改”一起消失，而且可能改回去。 |
| 5 | 冲突在写入时处理 | 哪条最新**按写入时间定，不让模型猜**。写入时就做冲突检测：同一属性来了新值，先把旧的标成“已过期”。不要等到检索时才发现，检索侧处理冲突很容易漏。 |
| 6 | 属性变化不等于冲突 | “三年前不吃辣，去年爱吃辣”是偏好变了，不是冲突。抽取时把**偏好**和**禁忌**分成两类：禁忌（过敏、安全）不随时间失效，偏好可以更新。**这个分类在设计时定，不由模型判断。** |
| 7 | 写入门槛 | 不是所有对话都存。只有三类值得写：明确表达的偏好、对我的纠正、重复出现的事实。闲聊和一次性回答不写。 |
| 8 | 分层 | 上下文窗口放当前对话；向量库加结构化存储放长期记忆；另有一层**工作记忆**放当前任务的中间状态，任务结束就清掉，不进长期库，否则以后检索就是噪声。 |
| 9 | 评测集 | 单独做一类“时间敏感记忆”题：故意问“三年前说过什么”，故意构造前后矛盾的输入，看取的是不是最新那条。指标不只看召回率，还看时间对不对、冲突处理对不对。**“把别人的事安在他头上”是最严重的错误，单独算一类。** |

## 2. 对应到墨衡：每部作品就是一个“用户”

视频里的“用户”对应墨衡的“一部作品”。每部作品已经有自己独立的数据库（`projects/<作品>/project.db`），天然隔离。下表逐条对照视频要点和现状：

| 视频要点 | 墨衡现在有什么 | 差距 |
|---|---|---|
| 抽取关键信息 | 每章审计（AUDIT_EXTRACT）抽事实、认知、伏笔；连贯细节（习惯、外貌、物件）记在生产回执里 | 细节只在回执里，不是正式记忆；没有“重复出现才写”的门槛 |
| 结构字段 | 账本事实带人物（subject）、属性（predicate）、来源章节、故事时间；认知带知情者、来源章节 | 缺“记忆类型/时效”字段，比如禁忌不衰减、状态取最新 |
| 混合检索 | 上下文按**人物编号**取当前事实（上限 1000 条），超预算按新旧裁剪；已有全文索引 `search_documents_fts`，但没用于记忆检索，而且默认分词不适合中文 | **没有按“本章要写什么”检索**。很早埋下、很晚才用的设定会被新旧裁剪挤掉（QC 设计 §1b 的已知局限） |
| 时间过滤和加权 | 单值属性（位置、状态、身份等）有新值时，旧值标为被取代（`superseded_by`） | 时间权重没有按类型区分 |
| 更新不删除、写入时处理冲突 | 已有：单值属性写入时就取代旧值，旧版本保留；同属性冲突在入账时检查，冲突的留提醒 | 基本到位，缺“禁忌”和“偏好”的区分 |
| 偏好/禁忌分类在设计时定 | 账本谓词有设计时定好的规则（单值/多值、时间基准） | 缺时效类别，见 §3.2 |
| 写入门槛 | 每章最多 12 条事实、3 条伏笔，本章人物优先（QC-1） | 门槛按数量定，不是按“明确设定、纠正、重复出现”定 |
| 工作记忆分层 | 规划候选、改写建议、审计中间结果都存在各自的记录里 | 没有明确划出“工作记忆不进长期检索” |
| 负责人的纠正 | 提醒可以“知道了”；改稿和回溯流程（B12）能改账本事实 | 负责人在写作中说的规矩（比如“林薇不喝咖啡”“别再写左手小指”）没有地方长期记住 |
| 评测集 | 有大量功能测试，没有记忆专项评测 | 全缺，见 §4 |

## 3. 设计：作品记忆库

### 3.1 三层

1. **本章上下文**：写这一章时交给模型的东西，按预算装入。
2. **长期记忆**：作品记忆库。复用现有账本表（事实、认知、事件、伏笔），加上新的“记忆条目”表，存正式化的细节和负责人纠正。每条记忆带统一的结构字段：类型、人物/实体、属性、故事时间、来源章节、写入时间、状态（当前/已过期）、原文出处。
3. **工作记忆**：本章的规划候选、改写建议、连贯检查结果、审计中间稿。章节入账后不进长期检索，只留在回执里供追溯。

### 3.2 记忆类型与时效（设计时定，不由模型判断）

| 类型 | 例子 | 时效 | 检索时 |
|---|---|---|---|
| 铁律 | 世界规则、能力和代价、作品禁区、负责人定的禁写内容 | 永不过期 | 本章相关的总是装入 |
| 身份事实 | 姐姐是谁、出身、真实身份 | 不衰减，可被揭示改写（保留旧版本） | 按人物装入，不按新旧加权 |
| 状态 | 位置、伤势、持有物、阵营、身体代价 | 同属性取最新，旧的标“已过期” | 只装当前值，近的权重高 |
| 关系与认知 | 谁信任谁、谁知道什么 | 按故事时间有效，可变化 | 按人物和故事时间装入 |
| 细节 | 外貌、习惯、口头禅、物件样子 | 可更新，但改动要有交代 | 按出场人物/物件装入，旧细节权重低 |
| 事件 | 已发生的事（下旨北伐、某人死亡） | 不可变，按故事时间排序 | 用于防止“同一事件发生两次”（跨章重复暂缓项的基础） |
| 伏笔与承诺 | 埋下的线索、对读者的承诺 | 开放直到兑现 | 规划提到或到期时装入 |
| 负责人纠正 | 你在写作中定的规矩、改稿结论 | 永不过期，优先级最高 | 相关时总是装入，冲突时以它为准 |

### 3.3 写入门槛

只写四类，照视频的三类加一类：
1. 规划、底稿里**明确设定**的；
2. 负责人的**纠正**；
3. 正文里**重复出现**的细节（至少两章提到才正式记住，一次性描写不记）；
4. 改变状态的**事件**。

审计抽取的其他一次性内容留在工作记忆。

### 3.4 写入时处理冲突

沿用现有规则：同属性的新值取代旧值，旧值标“已过期”并保留。新增两条：
- **禁忌类保护**：新内容和铁律或负责人纠正冲突时，不覆盖它，直接留提醒。
- **属性变化不算冲突**：比如偏好变了（不吃辣 → 爱吃辣），记成新版本，并标注“变化在第 N 章”。连贯检查以后就能分清这是“变化”还是“矛盾”。

### 3.5 混合检索：按本章要写什么来召回

**检索依据**是本章规划：目标、场景、出场人物、地点、事件、伏笔。步骤如下：

1. **结构过滤**：本作品；类型；本章人物、地点、物件；在本章故事时间有效；未过期。
2. **相关性排序**：第一期用中文关键词全文检索，把 SQLite FTS5 改用 `trigram` 分词，中文可以按子串匹配。第三期视评测结果再加向量（见 §6）。
3. **按类型加权**：铁律、身份、负责人纠正不衰减；状态和细节越近权重越高。
4. **装进预算**：替换现在“按人物编号取 1000 条再按新旧裁剪”的做法，由检索结果决定带入哪些。裁掉的照旧记录在 `omittedSoftSources`。

这一步同时解决 QC 设计 §1b 的已知局限：很早埋下的设定，只要本章规划提到相关的人、物、事，就能被召回。

### 3.6 规模

几千章时，一部作品大约有几万条记忆：
- 结构过滤走索引；
- 全文检索在本地 SQLite 内完成，毫秒级；
- 向量如果用，几万条在本地暴力计算也只要几十毫秒。

单部作品不需要额外的向量数据库服务。

## 4. 记忆评测集（单独一类，离线、确定性，不花模型费用）

| 题型 | 构造方法 | 通过标准 |

## 6. 负责人决定（2026-11-01）

1. **向量**：第 1、2 期不上向量。但墨衡对用户的承诺是能写 2000 万字的长篇，向量检索一定要做，放在项目收尾阶段（第 3 期从“视评测决定”改为“必做”）。
2. **负责人纠正**：两个入口都要，功能一致，只是作用范围不同：
   - 提醒里的“记住这条”：作用于那条内容涉及的人物、物件或事件；
   - 作品设置里的“写作规矩”：作用于整部作品。

   两者都按“负责人纠正”类型存，永不过期，冲突时优先。
3. **时间**：先完成第一要务（签约通过、教会模型创作），再做记忆库第 1 期。

## 7. 第 1 期实现（2026-11-01，负责人已确认）

### 7.1 做了什么

- **记忆表**：每部作品的数据库新增 `work_memory`（迁移 18），存每章生产回执里的连贯细节（习惯、外貌、偏好、物件、地点、关系），每条带人物/物件、细节类别、来源章节。记忆类型（§3.2）在第 2 期按类型召回时再加，第 1 期用不到。`work_memory_sources` 记下每章取自哪一版回执。
- **写入**：每次规划或写作取记忆前，先把新入账或回执有变化的章节补进记忆表，撤回的章节一并删掉。记忆由回执派生，随时能从回执重建；复制作品时清空，再自动补齐。老作品第一次用时自动补齐，不用迁移数据。
- **按规划召回**（替代原来“逐章读全部回执、取最新 40 条”）：
  1. 本章出场的人和地点、规划里点到名字的人和物，最新的在前；
  2. 规划内容带回来的物件和地点（与规划至少有两组字词重合），例如第 5 章埋下的物件，第 300 章规划提到它就能召回；
  3. 剩下的名额按新旧补齐，交给模型的条数（40 条）不比原来少。
- **防张冠李戴**：不在本章、规划也没点名的人物，他本人的习惯、外貌、偏好、关系不召回，即使字词相关；他的物件可以召回，并始终标着原主人。规划阶段由规划者决定谁出场，所以不排除任何人，上一章的人物优先。
- **人物状态**（位置、伤势、持有物）：仍由事实账本管理，同属性只保留当前值，旧值保留可追溯，这一点原来就有。

### 7.2 与设计稿不同的地方

- **第 1 期没有用 trigram 全文检索**。中文人名和物件名大多是两个字（沈砚、工牌、胶片），trigram 至少要三个字才能命中，会漏掉大部分。所以第 1 期的相关性改为直接比对“有区分度的两字组合”（与连贯检查用的同一套规则），在本地计算：3000 章、约 1.8 万条记忆，一次召回在测试里不到 1 秒（调试版），正式版更快。检索规模再大、或第 3 期加向量时，再引入索引。
- **铁律、负责人纠正**：世界规则现在随故事底稿整份交给模型，不会丢；负责人纠正属于第 2 期。

### 7.3 评测集（`tests/wm1_work_memory.rs`，离线、不花模型费用）

| 题型 | 结果 |
|---|---|
| 本章人物优先、新的在前 | 通过 |
| 时间敏感（第 3 章缠纱布、第 9 章拆纱布） | 第 9 章的在前，第 3 章的仍可追溯 |
| 久远设定（第 5 章物件，第 300 章召回，中间隔 1800 条） | 排第一 |
| 张冠李戴（不在场人物的习惯、外貌） | 不召回；他的物件可召回且标着原主人 |
| 规划点名的人 | 算作在场 |
| 重复细节 | 只保留最新一条 |
| 规模（3000 章） | 召回正确，耗时达标 |

另有两个端到端测试：写完两章后记忆表里有第 1 章的细节；章节撤回后它的记忆随之删除。

## 8. 第 2 期实施计划（2026-11-02，负责人已确认先做 WM-2a）

按 §5 的范围拆成四步。每步都是先写测试，跑完 10 步关卡再提交；评测集随每步扩充。

| 步 | 内容 | 涉及 | 评测 |
|---|---|---|---|
| WM-2a 负责人纠正 | 新增“负责人纠正”记忆（迁移 19，`work_memory` 加 `kind` 和作用范围）：<br>- 两个命令：`memory_correction_add`（作用于人物、物件或事件）和 `writing_rule_add`（作用于整部作品），另有撤销命令；<br>- 召回时纠正总是装入、排在最前；<br>- 规划和写手的输入里新增 `ownerCorrections`，提示词写明“冲突时以它为准”。 | 后端：迁移、仓储、命令、提示词<br>前端：提醒卡片加“记住这条”，作品设置加“写作规矩” | 纠正题：纠正和后来的事实冲突时，召回以纠正为准；整部作品的规矩每章都在 |
| WM-2b 写入门槛 | 细节至少在两章出现才正式记住；只出现过一次的细节留在回执里，不进召回。 | 后端：记忆派生规则 | 一次性描写不召回；第二次出现后召回 |

| WM-2d 事件时间线 | 已提交的事件按故事时间排成一条线，交给规划参考（最近的 N 条，加上本章规划点名的事件），并给“同一事件重复发生”的检查提供依据（检查本身仍属暂缓项）。 | 后端：事件读取、规划输入 | 事件题：已发生的事不再被规划成第一次发生 |

**负责人决定（2026-11-02）**：
1. 先做 WM-2a。
2. “记住这条”只放在计划提醒和连贯提醒（矛盾、口头禅）上。

### 8.1 WM-2a 实现

- **数据**：负责人纠正存在独立的 `owner_corrections` 表里（迁移 19），不和 `work_memory` 混放。`work_memory` 是从章节回执推导出来的，会随回执重建；纠正是负责人亲手写的，不能被重建冲掉。
  - 不填对象（`subject` 为空）的是整部作品的写作规矩，填了对象的只对那个人物或物件生效。
  - 撤销的纠正不删除，只记下撤销时间。
  - 复制作品时一起复制（`COPY_REMAP`）。
- **命令**：
  - `writing_rule_add`：添加作品设置里的写作规矩；
  - `memory_correction_add`：提醒里的“记住这条”，可以带 `subject` 和 `decisionId`；
  - `memory_correction_revoke`：撤销一条。

  这三条命令和文风样本一样，只存在本机，不生成版本、不占项目修订号。内容为空时拒绝，返回 `WM2_CORRECTION_CONTENT_REQUIRED`。查询用 `query_owner_corrections`。
- **交给模型**：r2 章规划（`ChapterPlanner::extend_input`）和写手（`WritingContext::extend_render_input`）的输入里都有 `ownerCorrections`，格式是 `{subject, content}`，包含当前生效的全部纠正。两个提示词都写明：纠正和其他内容冲突时以纠正为准。
- **界面**：
  - 待处理页里，`rememberable` 的提醒会显示“记住这条”，也就是暂缓内容里有 `plan` 或 `continuity` 条目的提醒（计划提醒、规划提醒、连贯问题）。点开后带出提醒原文供修改，“只对谁生效”可以不填。
  - 作品设置新增“写作规矩”一栏，列出全部生效的纠正，可以新增、撤销。
- **重试与写锁**：纠正的编号由命令编号算出，同一条命令重试不会记两次。三条命令都允许在生产进行中执行（加入 `writeLockAllowed`），从下一章开始生效。
- **欠账**：纠正不分对象全部交给模型，条数也不设上限，规矩多了以后提示会越来越长。等条数真的多起来，再按本章人物筛选。

  - `tests/store/wm2-owner-corrections.test.ts` 检查界面入口。
