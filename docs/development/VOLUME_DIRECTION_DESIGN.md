# VD-1：签约后的方向与阶段目标（设计稿）

状态：**负责人已确认（2026-11-02），VD-1a 到 VD-1e 已实现**　日期：2026-11-01　依据：PRD R2 §2、FR-BP-002、FR-VI-001、FR-VP-001/002/003；架构 R2 §10、§11、§16

## 1. 问题

第十二轮真实验收：十章全部写成，签约通过，但从第 4 章起，每章都是同一个动作——
“沿上一章线索找到一个节点 → 独自前往 → 修复一次 → 身体再坏一点 → 拿到下一条线索”。
反派十章没出场，林晚第 2 章后消失，小满（第 3 章登场）从未出现，第 7、8 章的章末钩子几乎逐字相同。

### 1.1 文档原本的设计

PRD 第 2 节的流程是：黄金三章 → 签约评估 → 通过 → **全书规划正式版（APPROVED）→ 卷意图 → 卷任务路线** → 当前章规划。
FR-BP-002 / 架构 §10 规定：正式版必须**吸收黄金三章的实际内容与签约证据**。
架构 §11 规定：卷任务路线要分出必做、可选、灵活、高潮、预留几类任务，并写明依赖关系和完成条件。
文档同时禁止两件事：开篇前生成全书章纲（FR-PITCH-002）；卷任务路线里出现章节列表（FR-VP-002）。

### 1.2 代码的实际情况

流程已经接通，`book_plan_revise → planning_create_volume_intent → planning_create_volume_plan` 都会执行，但三步全是确定性模板，**没有一次模型调用，也没读三章的情节**：

| 位置 | 写进去的内容 |
|---|---|
| `planning.rs::enrich_book_plan_from_opening` | 必须达成、关系方向、核心谜题、卷种子，全部是“开篇已提交事实不得违背；以 Canon 为准”这一类约束句 |
| `planning.rs::compile_volume_intent_from_authority` | 卷种子的 id 对不上 `volume-1`，于是卷作用回退成“承接全书战略并推进当前卷目标” |
| `planning.rs::compile_volume_plan_from_authority` | 必做、可选、高潮三个任务，目标就是上面那几句约束 |
| `provider.rs` 中 PLAN_CHAPTER_CRAFT 的提示词 | 输入里虽然带着 `volumePlanRoute`，提示词却没提它；`chapterGoalHint` 用的是默认的“推进当前卷任务……” |

结果，模型手里唯一的方向，只剩开篇前的那句读者承诺：“每章解决一个可验证的小谜题，同时让代价持续升级”。它照着这句话执行了七遍。

## 2. 目标与边界

**目标**：签约通过后，由模型读黄金三章的实际内容，给出全书方向和第一卷的阶段目标。每章规划都知道“现在处在哪个阶段、反派这一段要做什么、谁该回来”，然后按本章需要自己决定写什么。

**不做的事**（文档的硬约束）：
- 不生成章表。阶段是卷任务，不是章节列表；也不写“第 N 章发生什么”。
- 不新增数据表、权威来源或独立流程。内容装进全书规划、卷意图、卷任务路线，仍由同一个规划负责方提交。
  全书规划合同（book-plan.r1）的条目不允许多余字段，阶段放不进去，所以合同新增几个**可选**字段（VD-1a 实现时补充）：
  - 目标和方向条目（GoalConstraint、MacroDirection）加 `volumeNo`；
  - 卷种子（VolumeIntentSeed）加 `stages`（VolumeStage：id、goal、pressure、cast、newCast、turn、estimatedChapters）和 `climax`。
  老数据不受影响。
- 任务完成与否，仍然只按正文实际写出来的证据判定（现有的 `TASK_EVIDENCE_RECORDED` 规则）。计划写了不算完成。
- 不把方向当硬约束去拦章节。阶段和反派动向是给规划的参考，检查只作提醒（沿用 LD-1 的规矩）。

## 3. 方案

### 3.1 新增一步模型调用：PLAN_BOOK_DIRECTION（签约后执行一次）

**时机**：`book_plan_revise` 把种子版升为正式版时，替换掉 `enrich_book_plan_from_opening` 里的模板句。开篇事实的引用、签约证据、状态摘要这些确定性绑定**保持不变**。

**输入**（有界，不随全书增长）：
- 已确认的故事圣经：主角、反派、人物表及其登场章、机制、开篇走向；
- 故事核心：欲望、冲突、读者承诺、禁止提前揭示的内容；
- 三章的实际结果：每章的处境变化、大转折、主角赢的一局、章末钩子，取自已提交的章规划；三章正文的摘要不另外生成；
- 签约评估的结论：通过的平台、优点和风险条目；
- 平台与篇幅：例如番茄 120–180 万字，第一卷容量取卷意图现有的章数范围。

**输出**（JSON，直接写进全书规划正式版的现有字段）：

```json
{
  "protagonistMacroDirection": "主角整本书的成长弧线：从……到……",
  "mustAchieve": [{"id":"goal:book:1","volumeNo":1,"description":"……"}],
  "relationshipMacroDirections": [{"id":"relation:1","between":["陆照","某人"],"from":"……","toward":"……","volumeNo":1}],
  "majorMysteryGoals": [{"id":"mystery:1","layer":1,"answerInVolume":1,"description":"第一层谜底：……"}],
  "futureReservations": [{"reservationId":"reserve:mastermind","description":"租约幕后真正的操盘者","notBeforeVolumeNo":3,"mayForeshadow":true,"mayReveal":false}],
  "volumeIntentSeeds": [{
    "seedId":"volume-1",
    "description":"本卷作用：一句话",
    "stages":[{
      "id":"stage:1",
      "goal":"主角这一段要达成什么",
      "pressure":"反派/外部这一段做什么（出手、设局、逼近）",
      "cast":["这一段登场或回归的人物"],
      "turn":"段末的大转折",
      "estimatedChapters":4
    }],
    "climax":"本卷高潮"
  }]
}
```

**确定性校验**（不通过就把问题列给模型重做，最多 2 轮，沿用 `plan_chapter_with_feedback` 的模式）：
- 不得出现 `chapters`、章号列表或“第 N 章”字样（复用 `BOOK_PLAN_STATIC_OUTLINE_FORBIDDEN`）；
- 第一卷种子必须存在，阶段 3–6 个，每段 `goal`、`pressure`、`turn` 都不能为空，`estimatedChapters` 之和落在第一卷章数范围内；
- 人名必须来自故事圣经，或明确标注为新人物；反派至少在一半的阶段里有动作；
- 不得提前揭示故事核心里的禁止项：这些内容只能放进 `futureReservations`，且 `mayReveal` 必须为 false；
- 重做 2 轮后仍不通过：退回现在的模板内容，同时记一条“方向未生成”的提醒，生产不中断，但负责人能看到。

**成本**：每本书多 1–3 次规划模型调用，约 ¥0.05。以后每开一个新卷（B09）再调用一次。

**实现（VD-1a）**：
- `src-tauri/src/book_direction.rs`：输入、校验、写入、模型调用；反馈重做复用 `plan_chapter_with_feedback`。
- 写入时由系统统一编号：`goal:book:N`、`relation:book:N`、`mystery:book:N`、`reservation:book:N`、`volume-N`、`stage:卷:N`。预留一律 `mayReveal=false`。
- 退回模板时，记一条 `AUDIT_REMINDER`，分类为“规划提醒”。
- 只有配置了真实模型的网关才调用（`plans_book_direction`，默认跟随 `enforces_chapter_length`）。确定性网关保持原有模板，现有测试不受影响。

### 3.2 卷意图

`compile_volume_intent_from_authority` 改动两处：
- `seedId == "volume-1"` 能被现有的 `seed_matches_volume` 识别，卷作用改用种子的 `description`；
- 必须达成的目标改为：`volumeNo` 等于本卷的全书目标，加上种子里每个阶段的 `goal`。开篇事实的约束移到“不得违背”里，不再充当任务。

卷意图的其余字段（准入条件、出卷条件、预留、跨卷责任、篇幅范围）不变。

**实现（VD-1b）**：
- 卷种子带阶段时，“必须达成”依次是：各阶段目标（`goal:卷id:stage:卷:N`），然后是全书给本卷的目标（`volumeNo` 等于本卷）。之后照旧追加跨卷责任。
- 开篇已发生的事件不再变成“承接已发生事件……”的目标。
- 种子没有阶段时，结果与原来一致。

### 3.3 卷任务路线

`compile_volume_plan_from_authority` 按阶段生成任务：

| 来源 | 任务类别 | 依赖 | 完成条件（不变） |
|---|---|---|---|
| 每个阶段 | 必做 | 依赖前一个阶段 | 审计从正文里报告这一段的目标已经达成，并附证据 |
| 本卷的关系方向 | 可选 | 无 | `RELATION_STATE_MATCH` |
| 本卷要揭开的谜题层 | 高潮 | 依赖最后一个阶段 | `CANON_EVENT_EXISTS / MYSTERY_RESOLVED` |
| 预留 | 预留 | 不变 | 不变 |

任务的 `objective` 写真实剧情，例如“陆照第一次在三宗会审上拿出租约破绽”。`estimatedChapterCost` 取 `estimatedChapters`，仍是软估计。

**实现（VD-1b）**：
- 任务合同没有说明字段，所以阶段里的 `pressure`、`cast`、`turn` 不写进任务，留在全书规划的阶段里。VD-1c 按任务编号的结尾（`stage:卷:N`）对回去读。
- 关系和谜题条目带 `volumeNo` 时，只有本卷的进入路线；没有卷号的照旧都进。
- 高潮任务取本卷要揭开的那层谜题，目标写成“卷高潮；谜题层”。

### 3.4 每章规划拿到什么

PLAN_CHAPTER_CRAFT 的输入新增 `volumeDirection`（参考信息，不进硬约束）：
- 本卷作用；
- 当前阶段：第一个未完成的必做任务，以及它的目标、反派动向、该出场的人物、段末转折；
- 当前阶段已经用了几章，估计要几章；
- 后面还有哪些阶段，只列目标；
- 主要人物和反派最近一次出场在第几章（从已有的出场记录里算）。

提示词改为：先读 `volumeDirection`，再按本章在阶段里的位置决定本章做什么——推进目标、让反派出手、带回一个人物、喘口气，或者完成段末转折；本章该推进哪个任务，写进现有的 `activeTaskRefs`。**不要求每章都推进任务**，一个阶段写几章由规划按情节判断，估计章数只作参考。
`chapterGoalHint` 的默认值改成当前阶段的目标。

**实现（VD-1c）**：
- `book_direction::chapter_direction` 计算当前阶段：取第一个未完成的阶段任务。完成与否看审计写下的任务进度（`SATISFIED`）。`chaptersSoFar` 从上一阶段完成的那一章算起；第一卷的第一阶段从开篇第 3 章之后算起，后面各卷从本卷第一章之前算起。只统计本章之前完成的任务，重新规划较早的章节时，不会把后面章节的完成算进来。
- `book_direction::for_chapter` 从数据库读全书规划、本卷路线和任务进度。`craft_plan::last_appearances` 从前面各章的写作决定里，算出反派和配角最近一次出场在第几章。
- 两条规划入口都经过 `ChapterPlanner::extend_input`。有阶段时，输入里多出 `volumeDirection`。
- PLAN_CHAPTER_CRAFT 的提示词说明怎么用这些信息：
  - 按本章在阶段里的位置决定写什么；
  - 推进阶段目标时，把 `currentStage.taskId` 写进 `activeTaskRefs`；
  - 反派离场 3 章以上，本章要让他或他的手段出现；
  - 不提前写后面阶段的目标或卷高潮；
  - 超出预计章数较多时，往段末转折收。
- `chapterGoalHint` 没有改：r2 规划的提示词不读它，只有 r1 用。

### 3.5 审计

确认审计输入里带着当前卷的任务表（任务 id 和目标），没带就补上，让 `taskProgressCandidates` 能按正文报告“某阶段已达成”。判定规则不变，仍是证据加确定性门禁。

**核对结果（VD-1c）**：已经带着，不用改。上下文编译默认把本卷路线的全部任务（最多 100 个）放进 `plan_task_refs`，每个任务的目标都投影进 `authorityContext`，审计输入里就有这份 `authorityContext`。

### 3.6 提醒（只提醒，不退回）

接入现有的计划提醒，阈值待负责人决定：
- 反派连续 **N** 章不在场（建议 N=4）；
- 当前阶段点名要出场的人物，阶段过半还没出场；
- 一个阶段已经用掉估计章数的 2 倍，仍未完成。

**实现（VD-1d）**：
- `book_direction::reminders` 计算三条提醒，`ChapterPlanner::reminders` 把它们和 LD-8 的形状提醒一起记进本章的计划提醒，不退回重做。
- **反派缺席**：反派从上次出场算起，到本章已经连续 4 章（N=4）不在场景人物里，就提醒。出场记录以 `lastAppearances` 为准。
- **阶段人物**：阶段已写章数达到预计章数的一半，而阶段点名的人物自本阶段开始一直没出场、本章也没有，就提醒。
- **阶段超时**：已写章数达到预计章数的 2 倍，就提醒“往段末转折收”。
- **补记（第 15 轮）**：任务进度每个任务只存一条记录。后面章节重复报告“已完成”，会把完成章改成最新一章，`chaptersSoFar` 就会算错。现在任务已由别的章节完成后，后面章节再报“完成”或“进行中”都不再记录，只有“受阻”“失效”照常记录。更彻底的做法是在写入时保留首次完成的章，留待以后改数据层时再做。第 15 轮审计其实从第 4 章起就逐章报告了阶段完成，并不晚。

### 3.7 VD-1e：原地打转（真实验收第 14 轮，2026-11-02）

第 14 轮修仙十章全部写成，签约通过，字数达标。

**有效的部分**：
- 方向第 2 次生成通过：5 个阶段，每段都写了反派周砚舟具体做什么。
- 阿沅、陈师伯第 4–10 章几乎每章都在。
- 周砚舟在第 4–10 章里出场 5 章。
- 审计在第 9 章记下第一、二阶段完成。

**问题**：
- 第 4–8 章一直停在第一阶段。第 4、5、6 章的章目标几乎一样（“确认药方无误，首次让灰线在某人眼前浮现”），第 7–10 章还在数“第 N 次点燃”。
- 读者承诺里的寿元代价、三大宗的外部压力，正文很少写到。

**修正**：
- **创作账本**的 `endings` 每章加上 `goal`：前几章计划的 `chapterGoal`，由 `plan_crafts_before` 一并取出。
- **规划检查**：本章目标和最近 3 章任一章“几乎一样”就退回。判定方法是复用 `telling_pairs`：去掉虚词后的两字片段，较短一方的 60% 以上出现在另一方里。仍是 LD-1 的反馈加宽松放行。
- **审计提示**：对 `chapterPlan.activeTaskRefs` 里的每个任务都要报告进度。正文写到目标就报 `SATISFIED`，有推进就报 `ACTIVE`。
- **章规划提示**：本章目标要越过最近几章，不能重复。最近几章已经写到阶段目标时，本章写段末转折，进入下一阶段。
- **`volumeDirection.storyPromise`**（全书读者承诺）要留在纸面上：用异能时，写出故事圣经里机制规定的代价；反派背后的外部势力持续施压。

## 7. VD-2：第二卷以后（负责人已确认，2026-11-02）

### 7.1 现状

- 签约后的 PLAN_BOOK_DIRECTION 只给第一卷写阶段；后面各卷的种子只有一句 `description`。
- 换卷由 B09 负责：`volume_lifecycle::apply_next_volume_handoff` 调用自己的 `compile_next_volume_intent` 和 `compile_next_volume_route`。这两个函数不读全书规划的种子，写出来的仍是模板：“承接退出状态中的未完成任务 …”“在下一卷继续推进跨卷责任 …”“建立下一卷入口并推进当前主线”。
- 第一卷修好之前的毛病会原样出现在第二卷：卷作用空泛、没有阶段、规划只能照读者承诺原地打转。

### 7.2 做法

1. **新增模型步骤 PLAN_VOLUME_DIRECTION**，在换卷提交之前调用一次（约 ¥0.05）。
   - 输入（有界）：
     - 故事圣经；
     - 全书规划里的方向、各卷目标、谜题分层、预留；
     - 下一卷的种子；
     - 上一卷的实际结果：各阶段在第几章完成、最后 3 章的处境变化和章末钩子、退出状态里没完成的任务；
     - `lastAppearances`；
     - 下一卷的章数范围。
   - 输出：下一卷的 `description`（可以按上一卷的实际情况改写），以及 3–6 个 `stages` 和 `climax`，格式同 VD-1a。
   - 校验：复用 `book_direction::problems` 里和阶段有关的检查（阶段数、必填字段、预计章数之和、人物、反派出手、不写章表）。最多重做 2 轮，仍不过就退回现在的模板，并记一条规划提醒。
2. **写回全书规划**：提交一个新版本的全书规划，只替换下一卷的种子（`seedId` 为 `volume-N`），其余字段不动。全书规划仍由规划负责方提交，不新增权威来源。
3. **换卷编译**：种子带阶段时，B09 的下一卷意图和路线改用 `planning::compile_volume_intent_from_authority` 和 `compile_volume_plan_from_authority`（VD-1b 已支持任意卷号），上一卷未完成的任务和跨卷责任照旧追加；种子没有阶段时保持现状。
4. **每章规划**：VD-1c 的 `for_chapter` 已按卷读取，后面各卷的阶段起点（本卷第一章之前）也已处理，不需要改。

### 7.3 负责人决定（2026-11-02）

1. 换卷时生成的下一卷方向**自动采用**，与第一卷一致。
2. **允许**模型根据上一卷的实际结果改写下一卷的 `description`；全书目标（`mustAchieve`）和预留不动。

### 7.4 实现（VD-2）

- `book_direction::plan_volume`：读本卷信息、全书规划、故事圣经和上一卷的实际结果，然后调用 PLAN_VOLUME_DIRECTION。
  - 上一卷的实际结果包括：各阶段的目标和完成章、最后 3 章的目标、处境变化和章末钩子，以及 `lastAppearances`。
  - 检查用 `volume_problems`：先查不写章表、`description` 不为空，其余与第一卷共用 `stage_problems`。
  - 与 PLAN_BOOK_DIRECTION 共用 `run_direction`，同样是两轮反馈加宽松放行。
- `book_direction::with_volume_seed`：只替换这一卷的种子，阶段编号为 `stage:卷号:N`。
- `commands::direct_volume`：`volume_handoff` 提交之后、并且不是重放时执行。生成成功的话，按顺序做三件事：
  1. 提交一个新版本的全书规划，依赖上一个版本；
  2. 用 `planning_create_volume_intent` 重新编译这一卷的意图；
  3. 用 `planning_create_volume_plan` 重新编译这一卷的任务路线。

  新的意图和路线会替换 B09 换卷时编译的那一版。生成失败时，只提交一条“第 N 卷方向没有生成”的规划提醒。命令结果里的 `volumeDirection` 是 `PLANNED`、`TEMPLATE` 或 null（确定性网关）。
- **出错时**：`direct_volume` 出错不会让 `volume_handoff` 失败，因为换卷已经提交了。结果里的 `volumeDirection` 会记成 `{"status":"FAILED","error":…}`。重试换卷会走重放，不会再规划这一卷，需要负责人看到这个状态后另行处理（欠账）。
- **欠账**：
  - 全书规划的新版本直接经 `CommitService` 提交，没有走通用规划提交路径上的那些检查（比如签约是否过期）。
  - 每次换卷，意图和路线会先由 B09 编译一版，再由 VD-2 编译一版，多出两次提交。
  - 等以后把方向挪到换卷编译之前（按 §7.2 的原设计）时，这几项一起解决。
- **偏离 §7.2 的地方**：没有把换卷那次原子提交拆开，而是在它之后另做提交。中途失败时，会停在“换卷完成、方向未更新”的状态，这和现在的行为一样，可以继续写下去。

### 7.5 验收

十章验收碰不到换卷。`tests/b2_red_behavior.rs` 的两条 `vd2_*` 测试先插入第二卷，再调用 `direct_volume`：
- 一条检查第二卷的种子、意图和路线都跟着新阶段走；
- 一条检查写章表时退回并留下提醒。

真实的换卷验收，等以后做“把第一卷章数临时调小”的专项验收时再跑。
